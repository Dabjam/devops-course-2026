# Сравнение Git и SVN

### 1. Почему в Git ветвление «дешевое», а в SVN — «дорогое»?
* **В Git:** Ветка — это просто лёгкий 41-байтовый указатель (файлик) на конкретный коммит. Создание, переключение и удаление веток происходят мгновенно, так как не требуют копирования самого кода.
* **В SVN:** Ветвление реализовано через физическое копирование всей директории проекта на сервере в папку `branches/`. Это требует времени, расходует дисковое пространство и сильно нагружает сеть и сервер.

### 2. Можно ли в SVN сделать коммит без интернета? Почему?
**Нет, нельзя.** SVN — это централизованная система контроля версий (VCS). В ней вся история, ветки и база данных хранятся исключительно на одном центральном сервере. Для фиксации любых изменений (`svn commit`) необходимо постоянное и стабильное подключение к серверу. В отличие от SVN, Git — распределённая система, где каждый разработчик имеет локальную копию репозитория и может коммитить офлайн.

### 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
1. **Работа с очень большими монолитными бинарными файлами:** Файлы 3D-моделей, графические ресурсы, видео, аудио (например, в GameDev), с которыми Git работает медленнее из-за полного дублирования истории.
2. **Частичный доступ к репозиторию (Path-based authorization):** В SVN можно разграничить права доступа к отдельным папкам репозитория для разных сотрудников (например, подрядчику дать доступ только к папке `docs/`). В Git проект клонируется только целиком.
3. **Поддержка Legacy-систем:** Существующие старые проекты в банках, госсекторе и enterprise-системах, где миграция на Git слишком дорога или финансово неоправданна.
